# Code of conduct

## Expected conduct

Participate in good faith. Be respectful, specific, and evidence-oriented.
Disagree with ideas and implementations without attacking people. Make room for
questions, corrections, and contributors with different backgrounds or levels
of experience.

Do not harass, threaten, discriminate against, impersonate, or deliberately
humiliate another participant. Do not publish another person's private
information, credentials, private correspondence, or sensitive repository data.
Do not use project spaces for sustained disruption, spam, or unrelated
promotion.

## Project spaces

This policy applies to repository issues, pull requests, reviews, discussions,
release coordination, and other spaces represented as part of the ATS project.
It also applies when someone represents the project in a public venue.

## Reporting and enforcement

For ordinary conduct concerns, contact a repository maintainer through the
least-sensitive available project channel. Do not include private or dangerous
material in a public report. If a conduct report requires confidentiality, use
a public issue only to request a private maintainer contact and include no
sensitive details. The vulnerability-reporting route in `SECURITY.md` is for
security defects, not general conduct disputes.

Maintainers may edit or remove contributions, limit participation, or exclude a
participant when necessary to protect contributors and the project. Enforcement
should be proportionate, documented privately where possible, and avoid public
disclosure of sensitive details.

Security vulnerabilities follow [`SECURITY.md`](SECURITY.md), not this conduct
process. Contribution requirements follow
[`CONTRIBUTING.md`](CONTRIBUTING.md).
